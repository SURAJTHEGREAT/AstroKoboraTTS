# Backend API Only Mode

For developers looking to integrate Kokoro TTS processing into an existing architecture without utilizing the provided React frontend, the Express backend can be run in "API Only Mode."

## Enabling API Mode

Set the `API_ONLY` environment variable to `true` before starting the server. This tells Express to bypass serving the Vite frontend middleware.

```bash
API_ONLY=true npm run dev
```

You will see confirmation in the console: `Server running on http://localhost:3000 (API Only Mode)`.

## API Documentation

When running in API mode, or generally interacting directly with the backend, the following core REST endpoints are available.

### 1. Generate TTS (`POST /api/tts`)

Initiates the text-to-speech engine. Returns a Server-Sent Events (SSE) stream.

```bash
curl -N -X POST http://localhost:3000/api/tts \
  -H "Content-Type: application/json" \
  -d '{"message": "Hello, world.", "voice": "af_heart"}'
```
*Note: The `-N` flag is required to read the streaming SSE response in curl.*

### 2. Train Custom Voice (`POST /api/train`)

Uploads a `.wav` file to generate a new voice embedding.

```bash
curl -X POST http://localhost:3000/api/train \
  -H "Accept: application/json" \
  -F "username=admin" \
  -F "password=password" \
  -F "voiceName=my_custom_voice" \
  -F "sample=@path_to_local_audio.wav"
```

### 3. Fetch Analytics (`POST /api/analytics`)

Retrieves aggregated API usage statistics for registered clients.

```bash
curl -X POST http://localhost:3000/api/analytics \
  -H "Content-Type: application/json" \
  -d '{"username": "admin", "password": "password"}'
```

*For more detailed request/response schemas, refer to the root `backend_api.md` file.*
