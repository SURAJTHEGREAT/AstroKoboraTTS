# Backend API Only Mode

For developers looking to integrate Kokoro TTS processing into an existing architecture without utilizing the provided React frontend, the FastAPI backend can be run in "API Only Mode."

## Enabling API Mode

Set the `API_ONLY` environment variable to `true` before starting the server. This tells FastAPI to require authentication for core API endpoints.

```bash
API_ONLY=true uvicorn main:app --port 8000
```

You will see confirmation in the console: `Uvicorn running on http://0.0.0.0:8000`.

## Authentication

When `API_ONLY=true` is enabled, the `/api/tts` and `/api/voices` endpoints require the following headers for authentication:

- `x-client-id`: Your unique client ID.
- `x-client-secret`: Your unique client secret.

### Generating API Credentials

To generate a new set of credentials, use the `/api/clients` endpoint. This requires admin credentials (default `admin`/`password`).

**Endpoint:** `POST /api/clients`

```bash
curl -X POST http://localhost:8000/api/clients \
  -H "Content-Type: application/json" \
  -d '{"username": "admin", "password": "password", "clientName": "ThirdPartyApp"}'
```

**Response:**
```json
{
  "success": true,
  "message": "API Client generated successfully",
  "client": {
    "client_name": "ThirdPartyApp",
    "client_id": "client_...",
    "client_secret": "secret_..."
  }
}
```

## API Documentation

The following core REST endpoints are available.

### 1. Generate TTS (`POST /api/tts`)

Initiates the text-to-speech engine. Returns a Server-Sent Events (SSE) stream.

```bash
curl -N -X POST http://localhost:8000/api/tts \
  -H "Content-Type: application/json" \
  -H "x-client-id: YOUR_CLIENT_ID" \
  -H "x-client-secret: YOUR_CLIENT_SECRET" \
  -d '{"message": "Hello, world.", "voice": "af_heart"}'
```
*Note: The `-N` flag is required to read the streaming SSE response in curl.*

### 2. Fetch Voices (`GET /api/voices`)

Retrieves a list of all available voices, including built-in and custom blended voices.

```bash
curl -X GET http://localhost:8000/api/voices \
  -H "x-client-id: YOUR_CLIENT_ID" \
  -H "x-client-secret: YOUR_CLIENT_SECRET"
```

### 3. Blend Custom Voice (`POST /api/blend`)

Blends two existing voices to generate a new voice embedding. Note: This endpoint uses admin credentials in the JSON body for authentication.

```bash
curl -X POST http://localhost:8000/api/blend \
  -H "Content-Type: application/json" \
  -d '{"username": "admin", "password": "password", "voiceName": "my_blended_voice", "voiceA": "af_heart", "voiceB": "am_adam", "ratio": 0.5}'
```

### 4. Fetch Analytics (`POST /api/analytics`)

Retrieves aggregated API usage statistics for registered clients. Note: This endpoint uses admin credentials in the JSON body for authentication.

```bash
curl -X POST http://localhost:8000/api/analytics \
  -H "Content-Type: application/json" \
  -d '{"username": "admin", "password": "password"}'
```

## Running Standalone Backend with Docker

If you only need the TTS engine and not the frontend, you can run the backend container independently.

### 1. Build the Backend Image

Run this from the repository root:

```bash
docker build -f backend/Dockerfile.backend -t kokoro-backend ./backend
```

### 2. Run the Container

Start the backend in API Only mode, mapping port 8000 and mounting a volume for persistent data (models and database).

```bash
docker run -d \
  --name tts-backend \
  -p 8000:8000 \
  -e API_ONLY=true \
  -v $(pwd)/data:/app/data \
  kokoro-backend
```

The API will now be accessible at `http://localhost:8000`.

*For more detailed request/response schemas, refer to the root `backend_api.md` file.*
