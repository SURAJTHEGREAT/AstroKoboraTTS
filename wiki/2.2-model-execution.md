# Model Execution

The heart of the Kokoro TTS application is the local machine learning inference engine. This document provides a deep dive into how `kokoro-onnx` utilizes the ONNX runtime to synthesize speech efficiently without relying on external GPUs or cloud APIs.

## The `kokoro-onnx` and ONNX Runtime Integration

The application embeds `kokoro-onnx`, a Python package that loads and executes the `onnx-community/Kokoro-82M-v1.0-ONNX` model.

**ONNX (Open Neural Network Exchange)** is an open format built to represent machine learning models. By compiling the model to ONNX, it becomes highly portable and can be executed across various runtimes and hardware.

In this project, the ONNX Runtime is specifically configured to utilize the **CPU**. This makes the application highly accessible and easy to deploy via Docker or natively without requiring specialized NVIDIA hardware or complex CUDA setups.

## The Inference Pipeline

Generating speech from raw text is a multi-step pipeline inside the inference engine:

1. **Text Normalization and Splitting**
   - Raw user input often contains numbers (e.g., "100"), abbreviations, or complex punctuation.
   - The input is passed through a `TextSplitterStream`, which normalizes the text into spoken word equivalents (e.g., "one hundred") and segments long passages into sentence-sized chunks.

2. **Grapheme-to-Phoneme (G2P) Conversion**
   - The normalized text characters (graphemes) are mapped to phonetic sounds (phonemes).
   - This step is crucial for languages like English where spelling does not strictly dictate pronunciation (e.g., "read" present tense vs. "read" past tense).

3. **Conditioning with Voice Embeddings**
   - Kokoro TTS relies on pre-computed voice embeddings (like `af_heart` or custom blended voices).
   - These embeddings act as style vectors. They are injected into the neural network to condition the output, dictating the accent, pitch, and timbre of the generated speech.
   - *Note on custom voices*: While custom voices can be requested, `kokoro-onnx` currently defaults to a fallback simulation (`af_heart`) if dynamic loading of custom ONNX embeddings is not natively supported at runtime.

4. **Acoustic Modeling (The Neural Network)**
   - The sequence of phonemes and the voice embedding are fed into the core ONNX neural network.
   - The network outputs a representation of sound, typically a **Mel-spectrogram**, which defines the frequencies and energies of the speech over time.

5. **Vocoder Synthesis**
   - The final stage takes the Mel-spectrogram and uses a vocoder algorithm to convert it into a raw digital audio waveform.
   - `kokoro-onnx` streams this waveform out as a series of buffers, which the FastAPI backend then saves as `.wav` files and serves to the user.

## Neural Machine Translation (NLLB-200)

In addition to speech synthesis, the application integrates a local translation pipeline to support multi-language workflows.

### NLLB-200 and CTranslate2

**NLLB-200 (No Language Left Behind)** is a state-of-the-art encoder-decoder model by Meta AI designed to translate between 200+ languages. In this application, we use a distilled 600M parameter version quantized to **INT8** for a balance of speed and accuracy.

**CTranslate2** is used as the inference engine for the NLLB model. It is a C++ and Python library for efficient inference with Transformer models.

### Translation Workflow

1.  **Language Detection & Selection**: The system receives `source_lang` and `target_lang` parameters. If they differ, translation is triggered.
2.  **Sentence Batching**: Input text is split into sentences and processed as a batch by CTranslate2 to maximize throughput.
3.  **Beam Search / Greedy Search**: The engine uses optimized search algorithms to generate the most likely translation in the target language.
4.  **Handoff to TTS**: The translated text is passed directly to the `kokoro-onnx` inference pipeline, which uses the target language's phonemizer and default voice for synthesis.
