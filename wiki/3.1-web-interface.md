# Web Interface

The frontend of Kokoro TTS is a modern, responsive Single Page Application (SPA) designed to provide an intuitive user experience for both standard text-to-speech generation and administrative tasks.

## Technology Stack

- **React**: The core UI library used to build reusable components.
- **Vite**: A fast build tool and development server that provides rapid Hot Module Replacement (HMR).
- **Tailwind CSS** (if applicable based on typical stack): Used for rapid UI styling.
- **Recharts**: Utilized in the analytics dashboard to visualize API usage metrics.

## Key Features

### Text-to-Speech Console
The primary interface allows users to input text, select a desired voice embedding from a dropdown list (including both default and custom trained voices), and initiate the generation process. It features an audio playback component that handles the incoming stream of `.wav` chunks, ensuring smooth, sequential playback without user intervention.

### Administrative Dashboard
Protected by a simple authentication layer (typically username/password for admin routes), this section provides:
- **Voice Training**: A form allowing admins to define a new `voiceName` and upload a `.wav` file to simulate training a new custom voice embedding.
- **Analytics Visualization**: Interactive charts built with Recharts displaying total audio files generated, words processed, and average Time To First Byte (TTFB), aggregated by registered API clients.

## Managing Real-Time State

The UI relies heavily on managing the state of the Server-Sent Events (SSE) connection.
When generation starts, the UI transitions to a "loading" or "thinking" state. As the backend streams `{"status":"audio", "audioUrl": "..."}` events, the React application appends these URLs to a playback queue state. An invisible or customized audio player component listens to this queue, playing each chunk and automatically advancing to the next until the queue is empty and the SSE connection reports `{"status":"done"}`.
