# Analytics and Metrics

Monitoring the usage and performance of the TTS generation API is crucial, especially when serving multiple clients. The application includes a built-in analytics engine to track these metrics.

## Tracking Metrics in SQLite

Whenever a client (authenticated via `x-client-id`) successfully completes a text-to-speech request via `/api/tts`, the backend logs a new entry into the `api_client_stats` table in the `metadata.db` SQLite database.

The data captured per request includes:
- **`client_id`**: The ID of the API user making the request.
- **`words_processed`**: The total word count of the text string submitted for generation.
- **`ttfb_ms` (Time To First Byte)**: The latency measured in milliseconds from when the API request was received to when the first chunk of generated audio was emitted back to the client. This is a critical metric for evaluating the real-time responsiveness of the ONNX engine.

*Note*: In the context of these analytics, "total audio files generated" refers to the total number of completed API requests hitting the endpoint, not the individual fragmented streaming chunks produced during a single request.

## Analytics Visualization

The frontend provides an admin dashboard to visualize this data.
It makes a POST request to `/api/analytics` to fetch aggregated data. The Express backend runs an SQL query to group the statistics by `client_id`, calculating sums (total words, total requests) and averages (average TTFB).

The React frontend utilizes the **Recharts** library to render this aggregated JSON data into clean, interactive bar and line charts, giving administrators immediate insight into the system's load and performance.
